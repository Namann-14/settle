title: Telegram bot
description: Log personal expenses by messaging Settle on Telegram

Users link their Telegram once, then send messages like `lunch 250` or a voice note. The bot saves each one as a personal expense, so it shows up in the Spending tracker.

It uses the Telegram Bot API, which is free and needs no business verification. (An earlier WhatsApp version was dropped because Meta's Cloud API requires a verified business.)

## How it works

1. Telegram sends every update to `POST /webhooks/telegram` on `services/api`.
2. The API checks the `X-Telegram-Bot-Api-Secret-Token` header against `TELEGRAM_WEBHOOK_SECRET`.
3. The `update_id` is stored with a unique constraint, so when Telegram resends an update it is ignored.
4. Only private chats are handled. The chat is matched to a user; chats that aren't linked yet can only send `/start <code>`.
5. What happens next depends on the message:
   - Commands answer straight from the database.
   - Text is sent to `services/ai` at `/internal/extract/text`.
   - Voice notes are downloaded with `getFile` and sent to `/internal/extract/voice`, which transcribes them with Groq Whisper.
   - Both extraction routes are protected by the shared `INTERNAL_API_KEY`.
6. Extraction confidence decides the outcome:
   - **0.75 or higher:** the expense is saved straight away.
   - **Below 0.75:** a pending `AIExpenseDraft` is created and the user gets **Save** / **Cancel** inline buttons. Tapping one replaces the buttons with the result.
   - **No amount found:** the bot asks the user to resend with one.

Commands: `/help`, `/undo` (removes the last expense logged through the bot in the past 24 hours), `/today`, `/month`.

## Create the bot

1. In Telegram, open **@BotFather** and send `/newbot`.
2. Pick a display name (e.g. `Settle`) and a username ending in `bot` (e.g. `settle_money_bot`).
3. BotFather replies with a token. Put it in `TELEGRAM_BOT_TOKEN`, and the username (without `@`) in `TELEGRAM_BOT_USERNAME`.
4. Set `TELEGRAM_WEBHOOK_SECRET` to a random string (letters, digits, `_` and `-` only), e.g. `openssl rand -hex 32`.
5. Set `INTERNAL_API_KEY` to the same random value in both `services/api` and `services/ai`.

## Point Telegram at the webhook

Telegram needs a public HTTPS URL. Locally, run a tunnel:

```bash
cd services/api && uv run uvicorn app.main:app --reload --port 8000
cd services/ai && uv run uvicorn app.main:app --reload --port 8001
cloudflared tunnel --url http://localhost:8000
```

Then register the webhook and the command menu:

```bash
cd services/api && uv run python -m scripts.set_telegram_webhook https://<tunnel>.trycloudflare.com/webhooks/telegram
```

Check it with `uv run python -m scripts.set_telegram_webhook --info`. Re-run the script whenever the URL changes.

## Linking an account

Go to **Dashboard → Settings → Telegram** and click **Connect Telegram**. Telegram opens the bot through a `t.me/<bot>?start=<code>` link; tapping **Start** sends the code and links the chat. Codes expire after 15 minutes. The card switches to "Linked" once the bot has accepted the code.

## Vercel

`vercel.json` routes `/webhooks/*` to the `api` service.

- On the api service set `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` and `INTERNAL_API_KEY`, plus `AI_SERVICE_URL=https://<your-domain>` and `AI_ROUTE_PREFIX=/ai`. There is no service binding from api to ai: ai already binds to api, and Vercel rejects circular bindings, so the bot reaches ai through the public `/ai/*` rewrite, protected by `INTERNAL_API_KEY`.
- Set `INTERNAL_API_KEY` on the ai service too.
- Then run the webhook script with `https://<your-domain>/webhooks/telegram`. Use the production domain: preview deployments sit behind Deployment Protection.
