# apps/web/src/components/chat/chat-panel.tsx

**Purpose:** Full chat screen: header, message list, composer, suggestions and keyboard shortcuts, wired to the AI SDK `useChat`.

**Key contents:** `ChatPanel` uses `useChat` with a `DefaultChatTransport` to `/api/chat`, renders a hairline header (thread title from `useChatThreads`, "Settle AI", a secondary "New chat" pill), messages (user text in a muted 16px-radius bubble via MessageResponse, assistant via `AssistantMessage`), checkpoints, an inline error with "Try again" (`regenerate`), empty-state suggestions or model-provided follow-ups (`data-suggestions` parts) as secondary pills, the prompt box, and a shortcut hint line.

**Depends on / used by:** Uses ai-elements (conversation, message, checkpoint, prompt-input, suggestion, shimmer), `chat/assistant-message.tsx`, `suggestions.ts`, `use-chat-shortcuts.ts`, `@/hooks/useChatThreads`, `@/lib/chat-types`, `buttonClass` from `dashboard/panel.tsx`. Rendered by the dashboard chat pages.

**Decisions & caveats:** `chatId` doubles as the AI service thread id so memory and history follow it. An initial `?q=` prompt (from the home composer or search palette) is sent once on mount, one tick later via a cancelled-on-cleanup timeout: under StrictMode the first mount is torn down immediately and `useChat`'s cleanup calls `chat.stop()`, which used to abort a synchronous send before its request went out (and the ref then blocked the retry), so in-app navigation to a `?q=` chat silently sent nothing. It is then removed with `history.replaceState` to avoid re-asking on refresh without disturbing the stream. 'Restore checkpoint' only truncates client messages; the next request carries the checkpointId so the ai service forks from it. The modifier key label is resolved after mount to avoid hydration mismatch. New chat navigates to /dashboard (home composer); it lives in the header only (the composer's icon button was dropped as a duplicate; the shortcut still works). ai-elements are vendored, so they are restyled from here via className (the composer's InputGroup is reached with `[&_[data-slot=input-group]]:` selectors).
