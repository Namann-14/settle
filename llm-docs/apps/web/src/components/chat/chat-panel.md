# apps/web/src/components/chat/chat-panel.tsx

**Purpose:** Full chat screen: header, message list, composer, suggestions and keyboard shortcuts, wired to the AI SDK `useChat`.

**Key contents:** `ChatPanel` uses `useChat` with a `DefaultChatTransport` to `/api/chat`, renders a hairline header (thread title from `useChatThreads`, "Settle AI", a secondary "New chat" pill), messages in a `MessageScroller` (each turn a `MessageScrollerItem`; user text in a muted `Bubble` via `ChatMarkdown`, assistant via `AssistantMessage`), checkpoints (the Checkpoint pattern: a separator `Marker` with "Checkpoint" and an outline xs Restore button), message actions in `MessageFooter` (Copy on replies, Retry on the latest reply when an earlier checkpoint exists, Edit on the latest question; shown on the latest message, on hover for older ones, always on touch), an inline error with "Try again" (`regenerate`), empty-state suggestions or model-provided follow-ups (`data-suggestions` parts) as outline pills in a horizontally scrolling row, the composer (a form around `InputGroup` + `InputGroupTextarea` with one send/stop button), and a shortcut hint line.

**Depends on / used by:** Uses `@settle/ui` message-scroller, message, bubble, marker, input-group, button, tooltip and spinner; `chat/markdown.tsx`, `chat/message-actions.tsx`, `useRestoreChatCheckpoint`, `invalidateBalances`, `chat/assistant-message.tsx`, `suggestions.ts`, `use-chat-shortcuts.ts`, `@/hooks/useChatThreads`, `@/lib/chat-types`, `buttonClass` from `dashboard/panel.tsx`. Rendered by the dashboard chat pages.

**Decisions & caveats:** `chatId` doubles as the AI service thread id so memory and history follow it. An initial `?q=` prompt (from the home composer or search palette) is sent once on mount, one tick later via a cancelled-on-cleanup timeout: under StrictMode the first mount is torn down immediately and `useChat`'s cleanup calls `chat.stop()`, which used to abort a synchronous send before its request went out (and the ref then blocked the retry), so in-app navigation to a `?q=` chat silently sent nothing. It is then removed with `history.replaceState` to avoid re-asking on refresh without disturbing the stream. Restore calls the ai service first, which deletes the expenses later turns added and truncates the history; then it trims the client messages, and the next request carries the checkpointId so the graph forks. Approvals: `addToolApprovalResponse` plus `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses` send the answers, which resume the paused turn in place. `onFinish` refreshes balances, expenses and spending when the turn added an expense. Retry is hidden on the first reply because there's no earlier checkpoint to fork from, so the retried turn's expenses couldn't be rolled back. The modifier key label is resolved after mount to avoid hydration mismatch. New chat navigates to /dashboard (home composer); it lives in the header only (the composer's icon button was dropped as a duplicate; the shortcut still works). Built on shadcn AI Elements patterns (Chat, Message, Prompt Input, Suggestion), which ship as plain shadcn primitives rather than a component library. User turns are scroll anchors, so sending a message scrolls it to the top and `autoScroll` follows the reply. Enter sends, Shift+Enter adds a line, and IME composition is ignored. While a reply runs, submitting the form calls `stop()`. The submit button shows a spinner while waiting for the reply, a stop square while streaming, and an arrow otherwise. Loading text uses the `shimmer` utility from `shadcn/tailwind.css`.
